## 1. 核实方法

| 代号 | 方法 | 说明 |

| 项 | 内容 |

| 结果 | 确认。**已核实**，置信度 高 |

## 3. 假设与数值核实

### 3.1 60 FPS 与 16.7 ms

| 项 | 内容 |
|---|---|
| 假设 | 目标帧率 60 FPS，对应单帧预算 16.7 ms（NFR-01） |
| 依据 | 1000 ms ÷ 60 = 16.667 ms；浏览器 requestAnimationFrame 在 60 Hz 显示器上的刷新间隔 |
| 方法 | M3 算术 |
| 结果 | **已核实**，置信度 高 |
| 备注 | 若目标设备为 120 Hz 显示器，rAF 会以 120 FPS 回调。需求中的"60 FPS"应理解为**下限**而非上限；实现期须确认帧率不被无上限拉高而导致物理步长异常，Phaser 的固定步长配置可规避此问题 |

### 3.2 输入延迟 ≤2 帧

| 项 | 内容 |
|---|---|
| 假设 | 按键到视觉反馈 ≤33 ms（NFR-02） |
| 依据 | 2 × 16.667 ms = 33.3 ms；一帧用于采集输入并更新状态，一帧用于渲染。平台跳跃品类通常要求输入延迟落在 2~4 帧内 |
| 方法 | M3 算术 + 品类惯例 |
| 结果 | 指标设定合理，但实际值必须实测。**待实测**（PV-02），置信度 中 |

### 3.3 首屏可交互 ≤3 s

| 项 | 内容 |
|---|---|
| 假设 | 本地静态服务器下 3 s 内出现可交互主菜单（NFR-03） |
| 依据 | 2.11 实测首屏 JS gzip ≤600 KB；现有素材 327 KB，预计扩充至 5~15 MB 但按场景分批加载；本地服务器无广域网往返 |
| 方法 | M3 估算（基于实测体积） |
| 结果 | **待实测**（PV-07），置信度 中 |
| 风险与对策 | 若采用全量预加载，3 s 指标可能不成立。对策是改为分场景按需加载，该策略已隐含在仓库现有的 Boot / Preloader 双场景结构中（Preloader 已实现进度条），无需额外设计 |

### 3.4 localStorage 配额

| 项 | 内容 |
|---|---|
| 假设 | 单源可用配额约 5 MB（假设 A2、需求文档 2.5） |
| 依据 | 5 MB 是 Chrome、Firefox、Safari 长期沿用的默认值，但各浏览器实现不同且可能随版本变化 |
| 方法 | 未在目标浏览器实测 |
| 结果 | **待实测**（PV-05），置信度 低（行业惯例值） |
| 为何不影响需求成立 | 存档体积核算：DR-02 的示例 JSON 约 1.1 KB；即使 12 关全收集、20 格背包全满、全部技能解锁，估算也不超过 8 KB，比任何合理配额低三个数量级。且 NFR-05 与 EX-01 已定义配额不足时的降级路径（保留原存档 + 导出 JSON），因此该假设即使不成立也不会导致需求失效 |

### 3.5 主线时长推算

| 项 | 内容 |
|---|---|
| 假设 | 主线首通约 52 min，区间 50~70 min；完整体验 2.5~3.5 h |
| 核算 | 9 个常规关 × 4 min = 36 min；3 个 Boss 关 × 5.5 min = 16.5 min；合计 52.5 min（附录 B 各关目标时长取中值） |
| 方法 | M3 Node 计算 |
| 结果 | 算术成立。**待实测**（PV-08，依赖实际地图长度与敌人密度），置信度 中 |
| 完整体验估算依据 | 12 关 × 3 枚碎片，其中 1 枚需绕路或高难度跳跃，按每关额外 3~6 min 收集时间计约 45 min；新手死亡重试按每关 1.5 次、每次 1.5 min 计约 27 min；最佳时间挑战约 30~60 min；合计约 2.6~3.1 h，落在 2.5~3.5 h 区间内 |

### 3.6 经济闭环核算

| 项 | 内容 |
|---|---|
| 假设 | 单场景金币产出 1230~1880；满级一把武器需 1022 金币 |
| 核算 | 常规关 260~420 × 3 = 780~1260，Boss 关 450~620，合计 1230~1880。武器 n→n+1 级成本 `round(60 × n^1.5)`，n = 1..4 依次为 60、170、312、480，累计 1022 |
| 方法 | M3 Node 计算 |
| 结果 | 1022 ÷ 1880 = 54.4%，1022 ÷ 1230 = 83.1%，即"约占单场景产出的 55%~83%"。玩家在一个场景内可满级一把武器，同时仍有 208~858 金币余量购买消耗品，**经济闭环成立**。**已核实**，置信度 高（算术确定，实际掉落量待 PV-08 校准） |
| 反证 | 若沿用 AI 初稿的 `n^2` 公式，1→5 级累计 60+240+540+960 = 1800 金币，达到单场景最高产出的 96%、最低产出的 146%，玩家几乎不可能在通关前满级任一武器 → 该公式被否决，见 `docs/AI协作记录.md` MR-02 |

### 3.7 技能点收支核算

| 项 | 内容 |
|---|---|
| 假设 | 玩家最多可得 42 SKP，技能树全解锁需 46 SKP |
| 核算 | 12 关 × 3 枚回响碎片 = 36；3 个 Boss × 2 点 = 6；合计 42 |
| 方法 | M3 算术，并与 FR-11（每关恰好 3 枚碎片，DR-03 规定加载时强制校验）及附录 B（12 关、3 个 Boss）交叉比对 |
| 结果 | 三处描述一致，无矛盾。**已核实**，置信度 高 |
| 设计意图核实 | 42 < 46 意味着玩家必须放弃至少 4 点等值的节点，从而形成 build 取舍。技能树 21 个节点、单节点 1~4 SKP（DR-01 取值范围），46 点总消耗落在 21×1 = 21 与 21×4 = 84 的合法区间内，配置层面可实现 |

### 3.8 跳跃几何核算

| 项 | 内容 |
|---|---|
| 假设 | 跳跃初速度 480 px/s、重力 1300 px/s² 时，理论跳高约 88 px ≈ 2.8 瓦片 |
| 核算 | h = v² ÷ (2g) = 480² ÷ 2600 = 88.6 px；88.6 ÷ 32 = 2.77 瓦片 |
| 方法 | M3 Node 计算 |
| 结果 | 算术成立（理想模型下）。**待实测**（PV-04），置信度 高（推导）/ 中（实机） |
| 待实测原因 | Phaser Arcade Physics 采用离散时间步长积分，实测跳跃高度通常比理论值低 2%~5%，M1 里程碑需用实测值校准 |
| 反证 | AI 初稿参数 430 px/s、1200 px/s² → h = 430² ÷ 2400 = 77.0 px = 2.41 瓦片。角色碰撞体高 44 px（1.375 瓦片），2.41 瓦片跳高意味着可跨越的垂直高差仅约 1 瓦片余量，不足以稳定通过 3 瓦片高的台阶 → 参数被修订，见 `docs/AI协作记录.md` MR-03 |
