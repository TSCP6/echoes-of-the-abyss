## P1-01：读档后初始武器丢失

日期：2026-10-26。

### 原因

`wpn_shortsword` 和 `wpn_crossbow` 已有 WeaponDef，却没有 ItemDef。
背包读档同时用 ItemDef 识别槽位物品与装备，因此将这两把武器视为未知物品丢弃。
旧版随后再次保存时，还会把装备栏的 null 写回存档，造成持续丢失。

### 修改

1. `src/game/data/items.ts` 补齐遗迹短剑和轻弩的物品定义，支持读档、背包提示与重新装备。两者不加入商店；伤害、攻速、等级和弹药规则保持原配置。
2. `src/game/domain/configRegistry.ts` 增加 WeaponDef → 同 id、weapon 类 ItemDef 的启动校验，防止再次出现这种配置遗漏。
3. `src/game/domain/inventoryStore.ts` 读档只接受 weapon 类物品作为装备，避免将药水等非武器错误装入装备栏。
4. 对旧档执行保守恢复：仅当对应装备栏为空、武器等级记录证明持有该初始武器、且两个装备栏和背包均不存在该武器时，补回对应栏位。已有装备不覆盖，已有背包物品不复制，没有持有记录不发放。
5. `PreloaderScene.ts` 在成功读取所有存档分节后触发恢复；恢复使用原有 inventory 变更事件、脏标记与双键写入机制持久化，不改变存档版本或跳过校验。

## P1-02：切关监听累积、重复击杀奖励

日期：2026-10-26；基线：`ebf0a71`。

### 原因

`LevelScene` 和 `CampScene` 虽然定义了 `shutdown()`，却没有把它们绑定到 Phaser 的场景关闭事件。
因此每次进入场景都会再次订阅全局事件，离开时却没有执行原有的退订与资源清理。
`InputGateway` 另外使用匿名函数订阅游戏失焦事件，无法按实例移除，导致旧输入实例也被持续持有。

### 修改

1. 关卡和营地在每次创建时注册一次 `Scenes.Events.SHUTDOWN`，让原有清理代码实际执行；只退订本场景的回调，不清空其他模块的监听。
2. 关卡关闭先清除 `ready`，再释放战斗、弹丸、敌人、特效、拾取系统及教学引用；系统尚未创建时也可安全退出。只有仍持有当前玩法令牌的场景才清除令牌。
3. 输入网关使用具名失焦回调，场景关闭后自动销毁。销毁可重复调用，并释放本实例的监听与输入快照；Phaser 仍负责按键对象本身的销毁。
4. 失焦时立即清空 down/justPressed/justReleased 三类快照，避免暂停帧保留旧输入。
5. 每次重新进关重置检查点、Boss 唤醒标记、冲刺计时、越界计数和面板标志，不沿用上一次尝试的临时状态。

## P1-03：暂停页返回后游戏继续运行

日期：2026-10-26；基线：`813731b`。

### 原因

`UiLayer.close()` 从历史栈恢复上一层界面后，无论有没有剩余面板，始终发送 `ui:overlay` 的 `open=false`。
于是设置页已经回到暂停页，关卡却收到“所有面板关闭”的状态并恢复运行。
从暂停页进入操作说明后再返回也存在相同问题。

修复前在无头 Chrome 中复现：界面状态仍为 `paused`，但场景已非暂停，等待约 350 ms 后关卡计时从约 0.033 s 增至 0.383 s。

### 修改

1. 返回后根据实际界面状态发送面板通知：仍有上一层面板时发送该面板名及 `open=true`；返回 `none` 时才发送原面板名及 `open=false`。
2. 在 `events.ts` 注明 `ui:overlay.open` 表示切换后是否仍有面板，避免后续把“关闭子页”等同于“恢复玩法”。事件名称、字段和类型保持不变。
3. 场景原有的暂停/恢复消费者无需改动，设置、操作说明、背包、技能树和商店共用原有返回逻辑。
