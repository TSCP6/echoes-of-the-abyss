# 金币经济与检查点存档调整

日期：2026-10-28。用户已确认按轻量动作RPG方案修改。对应FR-09/10/11/12/13/15、DR-02/04、NFR-05、AT-31～47；保留既有编号。

## 调整原因

旧普通关金币较少、材料掉落未接入、64个金币显示对象会截断Boss大额收益。检查点虽存了字段却未在继续时恢复，宝箱仅在当前场景内幂等；金币/强化缺少统一保存通知，暂停没有保存退出入口。此次先修收益与续关闭环，再用固定奖励建立早期成长节奏。

## 当前规则

| 内容 | 规则 |
|---|---|
| 死亡 | 不扣金币；最近检查点重生，HP/SP回满，敌人重置，已获得的成长、宝箱状态保留 |
| 宝箱 | 各章节40/60/80金币直接到账，固定1/2/3强化残片；永久记录首开，不重复生成金币 |
| 强敌 | 精英保底1残片，三个Boss保底3/5/8残片，另保留lootTables随机物品世界掉落与满包余量 |
| 首通 | 普通关按章节30/60/90金币，Boss关100/200/300；重复通关不发首通奖励 |
| 金币实体 | 有面额，每次最多8个显示对象，池满合并到已有实体金额；不因对象池限制丢失配置收益 |
| 商店与强化 | 商品价格和原升级公式保留；前两关宝箱保证有足够金币/材料完成一次基础强化并留下补给钱 |
| 结算 | 分开显示本关实际拾取/宝箱入账、首通奖励、死亡损失（0）、当前钱包 |
| 继续 | 仅明确继续时恢复同关且实际地图存在的检查点；无效/旧档缺失回出生点；通关推进下一关，最终通关继续回第三营地 |
| 重玩 | 关卡选择及结算重试从起点，永久成长和宝箱首开保留；普通金币和敌人仍可重复获取 |

## 存档实现与兼容

- EconomyService、ProgressService、WeaponService、ShopService加入onDirty接线，SaveBootstrap统一注册。购买/升级只在完整事务成功后通知保存。普通金币和背包用400ms窗口合并；检查点/重要进度写入会提前兑现窗口；appLifecycle在hidden/pagehide时flush，减少关闭前窗口内丢失。
- SaveSystem仍使用原双键策略、checksum与损坏备份；schemaVersion仍为1，openedChests是progress可选新增字段，原健康存档不需清空或强制迁移。重试恢复写入后导出采集最新领域状态。
- 导入仅在主菜单：不超过2MB；先检查JSON/版本/checksum、完整分节形状、配置引用、进度唯一性、技能前置和SKP earned-spent收支，再显示摘要；用户点击替换后先完成双键写盘，再恢复参与者。非法文件或写盘失败保留旧档与当前状态。
- 新存档界面显示关卡/检查点/时间/游玩时长，支持导入预览、JSON下载；暂停支持保存退出、查看导出。写盘失败保持暂停并提供重试与导出。
- 修复快速“保存退出→继续”的竞态：旧Menu场景ready通知不能覆盖已排队的新Level/Camp界面意图。
- 用户手动清理浏览器站点数据、系统强制杀进程等情况仍可能无法保留最近未落盘状态；本次不新增云存档或多槽，维持纯前端离线边界。
