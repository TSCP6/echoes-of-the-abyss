# 十二关路线与区域差异化改造

日期：2026-10-27。需求依据：本次用户要求；关联 FR-01、FR-02、FR-10、FR-11、FR-13、FR-15、FR-16、DR-03、附录 B。

## 原因与设计

原关卡大多使用相同背景、草地与横向平地，区别主要是深渊和敌人的数量。用户要求每关有新的路线体验，三大区域具有明显背景和平台材料区别，营地同时美化，并完成可通关检查。

设计采用“每关一个主要空间概念、挑战前有安全立足点、奖励支路可回到主路”的原则。参考关卡设计访谈 [The secret to Mario level design](https://www.gamedeveloper.com/design/the-secret-to-i-mario-i-level-design)，应用每关核心概念和逐步展开的设计思路；具体布局与机关为本项目实现。区域美术来源和许可另见 `区域美术资源.md` 与 `素材许可清单.md`，全部随静态游戏本地发布。

## 实现与地图编辑约定

- `tools/gen_levels.py <id>` 只定向重建，缺省不再覆盖全部地图；十二关布局在 `tools/level_layouts.py`，公共 Tiled 模型在 `tools/level_model.py`。
- `tools/maps/1-1-authored.json` 保存改造前用户手工地图，重建 1-1 时保留其地形与对象，再添加本次踏点和路标。继续在 Tiled 手改后，先比对再运行生成器。
- 三份地形图集继续使用 32×32 网格、242 格、`terrain` 名称和既有 GID；地图图片路径也切到对应区域，因此 Tiled 编辑视图与游戏材料一致。
- `mechanisms` 是可选对象层。对象名称唯一；类型／类为 `switch`、`gate`、`crumble` 或 `sign`，自定义属性为 `group`、`order`、`label`。
- switch/gate 的 group 必须匹配；order=0 为普通符文，正整数为组内顺序。靠近后按重映射后的交互键激活；错误顺序清空本组，死亡重试重置全部机关。
- gate/crumble 使用对象矩形的真实坐标和尺寸。crumble 顶面有单向碰撞，踩踏后警告一秒，消失三秒再恢复；死亡重试立即恢复。
- 普通瓦片数字数组允许省略默认 encoding，与 Tiled 正常保存兼容，仍检查格式、尺寸和数组内容。Boss 区域、碎片及出生点数量校验保留。
- 真实高台落地测试发现默认 16px tileBias 可能漏分离高速下落，现按 32px 瓦片设定 tileBias=32；玩家速度、重力、跳跃参数不变。

## 验证方式与范围

`tools/audit_reach.py` 直接读取实际 JSON，不再分析生成脚本。按照玩家实际碰撞体、运动参数、实体遮挡与死亡区构造表面和弹道；主路线要求连续收齐三枚碎片、按序激活开关后抵达终点。静态审计不模拟战斗、脆桥计时或封印实体状态。

`tools/world_routes.check.mjs` 在隔离 Chrome 的真实 Phaser/Arcade 场景逐帧执行浏览器键盘输入，固定 60Hz 以避免隐藏标签页和短按采样伪影；从出生点走完整条路线，不用传送补足失败跳跃。几何路线给予玩家受伤无敌，敌人和物理继续运行；普通关断言真实结算，Boss 关先验证收齐碎片抵达终点且首领未死时门禁成立。机关、营地和 Boss 门禁另做单点交互回归，不能把测试辅助等同于真人通关难度验收。

## 人工试玩建议

启动 `npm.cmd run dev-nolog` 后，可用现有存档依次试玩1-2树冠、2-1下潜、2-2脆桥、2-3回折竖井和3-3符文，确认落点可见、路标明确、检查点重试合适；进入三处营地，用左右/A/D选择设施，E/Enter确认，也可直接点击。不要清空正式存档来解锁测试关卡。

真人难度、首次可理解性、长期稳定性和跨浏览器验收仍需分别进行。自动化本次使用受伤无敌辅助隔离地图阻断，不替代无辅助真人游玩。
