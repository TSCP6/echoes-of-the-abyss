# 出生点与检查点重生修复

2026-10-27，关联 FR-11 死亡与检查点重试、EX-11 掉图救援。

用户要求：尚未激活检查点时死亡应回本关出生点；只有实际激活检查点后才使用该点。

## 原因与修改

LevelScene 将 activeCheckpoint 初始化和重置为 cp_1，死亡重生与救援又默认选择检查点数组第一项。开局死亡会被直接送至尚未到达的检查点，并在下一帧错误激活该点。

- 初始及进关状态改为 null，激活回调仍记录实际触发的检查点 ID。
- 死亡和救援共用 respawnPoint：查找已激活 ID，否则使用 ctx.spawn。未知 ID 同样回出生点，不取后续检查点。
- 未激活时死亡事件的 checkpointId 使用地图出生对象名 player_spawn；事件字段类型与存档结构保持一致。

## 验证

tools/respawn.check.mjs 使用隔离 Chrome，通过真实伤害和死亡延迟流程检查。修复前 5 项失败：1-1 开局与连续死亡被送到 x=1344（应为 x=112），切入 1-2 被送到 x=1280；错误激活了 cp_1。

修复后 9/9 通过：未激活及连续死亡回出生点，激活 cp_1/cp_2 后分别回该点，重进同关和切关清除旧状态，未激活/已激活两种掉图救援，浏览器无脚本或控制台错误。

现有单元测试 202/202、vue-tsc、生产构建通过。未修改地图、生命恢复、死亡惩罚、敌人重置及收集物规则。
