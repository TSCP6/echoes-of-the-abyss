# Boss 战场镜头与边界修复

2026-10-27。用户反馈：1-4 进入 Boss 战时相机突然切偏，战场显示不全；玩家和 Boss 也能越过两侧。

## 根因

原先开战时围绕 Boss 临时构造 800×600 相机边界。Phaser `setBounds` 会立即钳制当前滚动值，随后 CameraRig 又把中心钳制到比视口更小的区域，造成开战首帧跳切。该区域也不包含右侧终点。`LevelContext.bossArena` 一直为空，玩家和敌人的世界边界碰撞均关闭，相机范围没有对应的物理约束。

## 调整

- 沿用 FR-02 规则 5：锁场时平滑居中到实际竞技场，不再直接设置小于视口的相机 bounds。按窗口宽高计算缩放，四周保留 48px 余量；转身、落地和阶段切换不改变战场构图。解除后恢复正常跟随与缩放。
- DR-03 增补：三个 Boss 地图新增对象层 `boss_arena`，恰好包含一个同名矩形，当前范围为 x=1792…2880、y=384…832。加载器验证尺寸、地图边界、Boss 和终点位置。普通关无须此对象层。
- 地图范围同时驱动两侧可见封锁与真实 Arcade 左右碰撞。玩家、Boss 和新召唤物都使用相同横向边界，正常移动、冲刺和受击退均不能穿出；不增加纵向天花板或妨碍掉落救援。
- Boss 击败时解除封锁。死亡重试恢复原有物理边界，重置 Boss 后再次靠近才重新开战；退出场景清理边界和图形。
- 背景反向补偿相机缩放，窗口变化时继续覆盖画布；HUD 保持原有屏幕锚定。
- 修改前确认 1-4、2-4、3-4 与生成器一致，只定向更新这三个地图及生成器。入口检查点、碎片、终点和其他关卡保持原位置。

## 验证

- 定向单测覆盖平滑过渡、横竖视口取景、解除锁场、真实 Arcade 边界分离、召唤物约束、地图契约和背景缩放。
- `tools/boss_arena.check.mjs` 使用隔离 Chrome，18 项场景检查全部通过，包括 1280×720、1024×768、720×960、移动/空中越界、两侧击退、击败解除、重试、后续召唤、切关清理，以及实际走到终点结算和重建关卡。
- 本轮 1-4 实测：开战首帧相机位移由约 298px 降至约 17px；过渡期间单帧最大位移约 17px，控制台无异常。
- `python -X utf8 tools/audit_reach.py`：全关可达性审计 0 违规。
- 全量 197 项单元测试、`vue-tsc --noEmit` 和生产构建通过。

结算重试按原有流程，在自动退回 Menu 的退场动画结束后操作。验证中另发现退场期间立刻点击“重试”会触发既有的 UI 状态竞态；本轮聚焦相机和战场边界，未修改 SceneDirector/UiLayer，快速点击问题留待单独修复。
