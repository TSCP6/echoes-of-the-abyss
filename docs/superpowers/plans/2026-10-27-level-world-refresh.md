# 关卡与营地差异化改造计划

用户已授权重新设计十二关的路线、环境与挑战，以及三处营地美术交互，并要求可通关验证。

## 设计与范围

- 森林遗迹：草根、木栈桥与遗迹石墙；教学回廊、树冠穿行、双层遗迹与守卫庭院各有路线。
- 地下洞窟：冷色矿岩、水晶与熔岩；下潜矿道、崩塌石桥、折返攀升与蛛巢竞技场。
- 天空神殿：云海、白金平台与星辉建筑；浮岛接力、回廊分流、顺序机关和最终祭坛。
- 每关保留三枚唯一回响碎片和检查点，主路与奖励支路区分；挑战前提供安全立足点、指示与重试位置。
- 通过 Tiled 对象层定义机关：可交互开门／架桥、按序激活符文、踩踏崩塌且可恢复的平台。所有状态随死亡重试重置，机关不改战斗数值。
- 营地采用场景内设施构图与明确的鼠标、键盘反馈，复用商店及选关服务。
- 保留现有 1-1 手工地图布局；从当前地图捕获可重建基线后在其上改进。其他十一关已核实与生成器一致，可定向重建。
- 保留工作区现有 LevelScene 重生点修复与 tools/respawn.check.mjs，不夹带其既有改动进入提交。

## 实施顺序与职责

1. 核对当前代码、手工地图与需求附录 B；记录基线。
2. 并行制作三主题背景／瓦片资源、营地场景，以及直接读取实际 JSON 的可达性审计；各自限定文件所有权。
3. 为机关的激活顺序、距离、崩塌恢复和重试重置编写回归测试，再实现领域状态与 Phaser 呈现系统。
4. 重设计十二关几何布局、分支、敌人部署、机关和路标；保留 Boss 锁场契约。将可重建配置同步到生成器。
5. 集成主题、机关、地图加载兼容与场景清理；更新需求变更记录和 Tiled 编辑约定。
6. 运行实际地图审计、Python 回归、Vitest、类型检查、生产构建与美术帧校验。
7. 在隔离浏览器运行十二关真实 Arcade 路线与新增机关、三场 Boss 进场／胜利门禁、三个营地交互及视口适配检查，保存图像和结果。跳跃测试不以传送替代通关；单独注明跳跃线路与战斗测试的边界。
8. 独立代码审查，修正发现后复验，检查本任务暂存差异，创建本地提交；不推送。

## 验收证据

以本次实际执行结果记录每关终点与碎片可达性、真实物理跳跃及机关检查；不沿用历史验收次数。人工难度手感、长期稳定与跨浏览器验收另列。
