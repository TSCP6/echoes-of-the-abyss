# 跳跃与金币拾取调整

日期：2026-10-27。范围：小幅降低跳高与滞空感，修复敌人掉落金币无法及时拾取。

## 跳跃手感

- 起跳速度保持 `560 px/s`，重力从 `1040` 增至 `1140 px/s²`，水平移动与松键短跳逻辑不变。
- 理论最高跳高从约 `150.8 px` 降至 `137.5 px`，同高度落点的理论滞空从约 `1.077 s` 缩短到 `0.982 s`。
- 在独立无头 Chrome 中长按真实 Space 键测量：实际最高跳高 `146.13 → 132.92 px`，落地耗时约 `1.06 → 0.96 s`。物理按固定步长积分，实测值略低于连续公式值。

原先尝试的重力 `1160` 会影响旧地图中的四格台阶和跨沟路线，因此采用更温和的 `1140`。
同时对地图作三处最小适配：

1. 2-1 的高平台从 `(23,18)~(26,18)` 向左延长到 `(22,18)~(26,18)`，保留四格台阶跳跃余量。
2. 3-3 第一段地面右缘从第 45 格延长到 46 格；第二段从 90 格延长到 91 格。
3. 对应两条深渊死亡区同步缩窄一格，避免与新增地面重叠。

生成器与 `public/assets/levels/2-1.json`、`3-3.json` 同步更新，其他十张地图未重新生成。
生成前已确认这两张地图与原生成器结果一致，未覆盖额外的手工地图编辑。

可达性审计原先把旧运动参数写死在 Python 中；现在直接读取 `playerDefaults.ts` 的跳跃、重力、行走速度，以免实际改了手感，审计仍使用旧参数。

验证：十二关 BFS 审计 `violations: 0`；真实浏览器通过 2-1 四格台阶和 3-3 两次跨沟跳跃，均正常落到目标地面或平台。

## 金币拾取

根因：原先拾取和磁吸共用 `0.4 + 3.0 = 3.4 s` 的等待门槛，所以刚掉落的金币即使与人物接触也无法拾取。

修改后的规则：

- 接触距离内的金币从掉落首帧起就可拾取，与掉落动画时长无关。
- 非接触的掉落金币保留 `0.15 s` 的散开动画，之后在原有 `96 px` 范围内开始吸附。
- 地图预置金币保持无需等待即可吸附。
- 优先处理接触拾取，再计算磁吸方向，避免金币与人物中心重合时除以零，产生 NaN 速度。
- 拾取时清零速度并禁用物理体、隐藏金币，保持单次入账和对象池复用行为。
- 金币数量、吸附距离、吸附速度与金币上限规则未改变。

新增四项回归测试：首帧接触即入账且不重复、150ms 后附近掉落开始吸附、中心重合不产生 NaN、预置金币立即吸附。
前三项在旧代码上失败，修复后全部通过。

真实浏览器中，附近掉落约 `0.29~0.31 s` 拾取；在测试浏览器中实际击杀一只巡逻敌人后，5 枚金币于下一帧开始入账，约 `0.24~0.27 s` 全部拾取。
这些是人物位于吸附范围内的测量值，远处金币仍需靠近。

## 验收

刷新游戏后，长按 Space 比较最高点与落地速度，再试短按确认仍可小跳。
靠近敌人击杀后应马上开始拾取金币，不必站在掉落旁等待三秒；直接碰到新掉落金币应立即入账。
如已有后续关卡进度，可再检查 2-1 的高台和 3-3 的两处深渊，确认可以正常通过。
